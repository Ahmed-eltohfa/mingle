01 · Overview

What is Mingle?

Product idea

Mingle is a social network-style application where authenticated users can create and discover updates, interact with posts, and manage a personal profile.

Primary experience

The home feed is the center of the product: posts are loaded from the API, rendered as cards, and progressively fetched as the user scrolls.

Audience

People who want a lightweight space for personal updates, visual media, conversation, and quick social actions.

Current product surface

Authentication, home feed, post creation, explore, profile, edit profile, saved posts, comments, responsive navigation, and reserved routes for future features.

Client

Angular 22.1.5, TypeScript 6, Angular SSR, standalone lazy-loaded routes, responsive layout components.

Server

Node.js with Express 5.2.1, CORS, dotenv, JWT, bcryptjs, Multer, and async request handlers.

Persistence

MongoDB is accessed through Mongoose. Uploads are exposed from the server's /uploads directory.

03 · Features

Core user journeys

Join and sign in

  • Registration with name, username, email, and password.
  • Password hashing with bcryptjs.
  • JWT login token with one-day expiry.
  • Guest and authenticated route guards.

Share and discover

  • Create posts with text and up to five media files.
  • Image and video rendering with alt text.
  • Home feed sorted newest first.
  • Explore post and user search.

Interact and manage

  • Like and unlike posts and comments.
  • Save and unsave posts.
  • Create, edit, delete, and like comments.
  • View and update profile information.

Responsive navigation includes side navigation on larger screens and bottom navigation on smaller screens.

04 · Feed pagination

Infinite scroll with server pagination

Backend contract

GET /api/posts?page=1&limit=10 { success: true, data: { data: [ ...posts ], page: 1, limit: 10, count: 10 } }

Client behavior

  • An IntersectionObserver watches a bottom sentinel.
  • Requests are guarded so only one page loads at a time.
  • New pages append to the existing signal.
  • Duplicate post IDs are filtered.
  • Loading stops when a page contains fewer than 10 posts or is empty.

05 · Data model

Domain objects and relationships

User

Identity, email, hashed password, role, bio, avatar, deletion status, and references to saved posts.

nameusernameemailavatarsavedPosts[]

Post

Author, text content, media collection, visibility, likes, timestamps, and soft-delete fields.

authorcontentmedia[]likes[]visibility

Comment

Text, user, post, optional parent comment for nesting, likes, timestamps, and soft-delete fields.

contentuserpostparentCommentlikes[]

Relationship summary

A user authors posts, comments belong to both a user and a post, posts maintain a list of users who liked them, and users maintain saved-post references.

06 · API map

Server routes at a glance

Authentication · /api/auth

  • POST /register creates an account.
  • POST /login returns a JWT.
  • GET /protected checks a legacy auth middleware path.

Users · /api/users

  • GET /me retrieves the current user.
  • GET /:userId retrieves a user.
  • PATCH /:userId updates profile and avatar.
  • DELETE /:userId removes a user.

Posts · /api/posts

  • CRUD operations and paginated feed.
  • Search and saved-post retrieval.
  • Like/unlike and save/unsave actions.
  • Multipart media upload support.

Comments · /api/comments

  • Create and list comments by post.
  • Update and delete owned comments.
  • Like, unlike, and inspect comment likes.

08 · Running the project

Local development workflow

Start the API

cd server npm install npm run dev

The server uses PORT from the environment, defaulting to 5000. The client currently targets localhost:3000 for API calls, so align the configured port before running end to end.

Start the client

cd client npm install npm start

Open http://localhost:4200/. Production build: npm run build. Unit tests: npm test.

Required environment

Configure the MongoDB connection and JWT secret in the server environment. The client and API must agree on the API host and port. Authenticated requests require the JWT interceptor/token flow.
